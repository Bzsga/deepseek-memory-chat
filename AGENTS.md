# DeepSeek 记忆聊天

Unified Kotlin/Compose Android host + React chat interface + FastAPI shared service.
Current requirements and interfaces are documented in [the merge contract](docs/merge-contract.md). See the [README](README.md) for current distribution entry points and the [app update guide](docs/app-updates.md) for Android package and signing metadata. Historical releases and validation evidence are recorded in the corresponding `docs/release-*.md` files. Broad old-data/API compatibility is unnecessary.

- android/: native chat host, local Room originals and editable memories, imports, BYOK, updates. web/: official DeepSeek React UI and local IndexedDB chat. backend/: one registered identity, admin and weekly quota ledger for chat and organization.
- Service /deepseek-api/, web /deepseek/, public origin https://digimonlegend.com. Weekly boundary Monday 00:00 Asia/Shanghai. User sees a single remaining count; actual chargeable upstream requests share it. Local operations and BYOK do not consume server allowance.
- Keep originals, stable message/branch IDs, source scope, edits, pinned entries and raw snapshots. Derived memory is background context; creating continuation chat never automatically calls a model. Preserve natural user-perspective recollections and gentle re-entry.
- Chat bodies and archives remain local by default, with model requests, explicit public shares and optional private account sync as defined transfers. Private sync defaults off account-wide, preserves conflict copies, pauses without erasing cloud data, and exposes explicit cloud clearing that also disables sync. See docs/conversation-sync.md. Shares persist selected body text, images and attachment metadata until owner revocation; exclude reasoning/actions/memory/unselected branches. Public preview is read-only, confirmed import atomically appends originals/images/source evidence, and all sharing/sync operations use zero model quota. See docs/conversation-sharing.md. Ordinary sending authorizes automatic context selection and at most one extra original-segment compaction request when required; show activity and count the extra call. Preserve originals and provenance, bound continuity background as well as messages, invalidate stale branch/edit/account writes, and never replay uncertain compaction. The chat gateway persists identities, quota/call metadata and attachment ownership. Background image jobs also persist owner-scoped status and temporarily retain generated results for 24 hours so page destruction can recover them; prompt text stays in process memory and only its hash is durable. Disconnecting or switching screens must not cancel these jobs or redispatch them. Separate explicit native organization jobs temporarily retain selected input and results for recovery, with 24-hour expiry. Plaintext BYOK keys remain on the device and must not be sent to this backend. An optional passphrase-encrypted key backup uses a separate account-scoped sync document.
- Use one native login in APK. Chat HttpOnly cookie and native Bearer share the same Accounts identity. Keep strict trusted-main-page WebMessagePort boundaries. Imported content is untrusted data.
- Chat is a full-screen official chat-demo-based web page, with a local guest workspace isolated from every registered account. Guests can use a personal DeepSeek Key and local chat/continuation features. Cloud sync and managed service require account eligibility. Public share creation requires an authenticated account. Only server-issued admin roles can access developer tools. There is one settings center. Android opens native detail screens from the relevant settings section. Keep guest-safe and offline access. Memory and account navigation remain available.
- WebView minimum is 105: use compatible viewport fallbacks. Reject zero/nonfinite viewport measurements and retain the last positive size during native resizing. Normal desktop/mobile screenshots alone do not cover these failure states.
- Mobile chat uses real document scrolling so WebView has native content/scroll range. Fixed header/composer, keyboard inset, reading/follow state and loaded-history pagination remain coordinated. API31+ ScrollCaptureCallback also maps that document on mobile and the message node on desktop. Preserve cancellation/overlay/session guards. Real device screenshot behavior requires separate evidence from DOM/geometry checks.
- When self-service registration is open, signup without an invitation grants basic cloud-sync eligibility. A supplied invitation must be valid and single-use. Consume invitations and apply their grants atomically. Existing accounts retain their grants. Administrators can adjust individual accounts and control self-service registration independently of global feature access. Cloud revocation pauses sync while keeping login, personal API and explicit cloud deletion available. Keep guest chats on-device and copy them into a signed-in workspace only with confirmation. Chat keys are configured per device/account. Personal keys use the separate encrypted browser vault and direct provider endpoints. Keep account/sync/share transport free of model credentials, isolate file IDs by provider scope, avoid automatic personal paid retries/fallback, and keep provider changes separate from account-ending events. Personal image requests use the configured service directly, using the trusted Android bridge when supported. Managed image requests use explicitly labeled managed allowance. See docs/personal-deepseek.md.
- Eligibility for managed chat, managed image and cloud sync can also be opened independently to all signed-in accounts from Android Developer Tools → Users and Invitations → Global Feature Access. See [admin feature settings](docs/backend.md#管理后台). Turning off a global grant falls back to the stored account grant. Apply cloud sync consent and quota rules independently of eligibility.
