# Unified DeepSeek project contract

User authority: merge both development products, use one shared weekly allowance, no old-data/API compatibility required, remove original projects after delivery. Keep raw chats local by default. Users may explicitly enable private account conversation sync or create selected public shares. Preserve attribution 作者：半盏丶时光 / 由GPT-6制作 and MIT licenses.

## Product and runtime
- Android is Kotlin/Compose host (existing android/), opening full-screen React chat in web/ without duplicate native chat top/bottom navigation. Guest welcome uses official chat-demo styling; new-chat is always available. Guests may send using their own DeepSeek or compatible provider key and create local continuations. Use a separate guest database, provider vault and settings. Do not initialize account-only sync or spend managed quota as a guest. Memory and account remain accessible from the chat sidebar. The sidebar and native settings tab lead to one settings center with platform-aware actions. Original import and full memory workflow remain available.
- One FastAPI backend in backend/, one Store/account identity. Native API origin https://digimonlegend.com/deepseek-api; web at https://digimonlegend.com/deepseek/. Web API_ORIGIN=/deepseek-api/chat.
- Backend router prefix /chat. Runtime/quota/images use /chat/api/runtime, /chat/api/quota and /chat/api/images. Provider calls use /chat/anthropic/v1/messages, /chat/anthropic/v1/files and /chat/v1/tools/asr|tts. Cookie deepseek_session carries the Accounts token, scoped Path=/deepseek-api; Secure; HttpOnly; SameSite=Strict. Cookie and native bearer authenticate the same registered owner.
- Registration requires a single-use invitation and has no total-user cap. Invitations and accounts have independent grants for managed chat, managed image generation, and cloud sync. Legacy accounts and invitations inherit their existing grants. Chat uses the managed provider by default when granted. Account-level decisions take precedence over user redemption. Revoking a grant blocks future actions that depend on it.
- Calendar week: Monday 00:00 Asia/Shanghai; reset_at is following Monday. Public/default/user caps are weekly; native API fields weekly_limit/user_weekly_limit/user_weekly_remaining etc. Chat and organize consume the same ledger, each actual chargeable upstream dispatch = 1. Local import/view/edit/export = 0. Model listing/file deletion = 0. Chat/file/ASR/TTS upstream POST each consumes 1; classification remains reporting only.
- Store contract for chat router: begin_chat_call(owner_id, kind) returns call id and atomically verifies the account, the grant for that call kind, and shared quota before counting one dispatch. finish_chat_call(call_id,status) records outcome without refunding a sent request. Gateway validates payload and ownership before counting the dispatch. File ownership stays server-side, no bodies persisted.
- Native login is authoritative inside the APK. The native host sets/clears HttpOnly API cookie from its encrypted account token; redirects to login/register in embedded chat trigger native Account screen rather than a second login. Browser uses router HTML auth forms.

## Local WebView bridge
Trusted exact main page https://digimonlegend.com/deepseek/ only, using WebMessagePort (no broad addJavascriptInterface). Handshake: native posts JSON {type:"deepseek.connect",version:1} with one port, fixed origin https://digimonlegend.com. Both sides enforce bounded JSON (2 MiB), version 1, request id; imported text is data.
Web→native: {version:1,id,type:"organize",payload:{conversationId,title,messages:[{id,role:"user"|"assistant",content,createdAt?}]}} current selected branch only. Native saves raw source as import, opens existing selection/preparation; smart request remains explicit. Web sends exactly original visible text, no thinking/tool prose.
Web→native: {version:1,id,type:"memory.open"} opens native memories; {type:"account.open"} opens native account; {type:"settings.open",payload:{section}} opens a native settings detail when the trusted handshake advertises settingsSections. Supported sections are service, data, about and developer. An older host can still handle settings.open without a payload. Native settings navigation can request the general, data or about tab using the trusted main page with #settings, #settings/data or #settings/about. Memory and account navigation are available to guests. The developer section is restricted to administrators. Browser login uses the same backend login/register route; native settings actions are shown only with a trusted port. Native responds {version:1,id,type:"ack",ok,error?}.
Web→native: {version:1,id,type:"share.link",payload:{url,title}} opens the Android ACTION_SEND chooser. Only canonical HTTPS links under the current production `/deepseek/share/{id}` are accepted. ACK means the chooser started. Message delivery remains under user control.
Native→web: {version:1,id,type:"continuation.create",payload:{title,text,sourceArchiveId}} creates a new LOCAL session and stores text as dedicated background continuity context, never an already-sent user message and never auto-dispatches a model call. User types the next message; short-chat context may be original text. Background is included once with future model requests, not shown as an artificial assistant/user utterance. Source remains native memory. Web responds ack. No replaceHistory call: append new chat.
Native exporting archives offers “在这里继续聊” using current full selected export text, plus existing external export tools.
Ordinary chat uses automatic context management. Manual native organization is an auxiliary workflow; it is not a required step for continuing the same conversation. Web account quota indicator gets runtime weekly_quota or GET quota.

## Automatic context and conversation files
- Sending selects recent whole rounds, applicable memory and relevant originals within an automatic 936,000-token estimate for the current 1M model window, reserving 64,000 for response/protocol space. Legacy 32K/64K/128K values normalize to this policy. Full `continuity` is stored/exported and selected within that budget. The model context remains finite and summaries can omit details.
- When needed, a send may make at most one additional semantic compaction call through the authenticated chat gateway. It summarizes original segments with source IDs and fingerprints, never recursively summarizes earlier summaries. Both model calls consume normal quota; local selection/edit/export consumes none. Failed or uncertain compaction is not automatically replayed.
- Keep every original and branch. Derived memory must match the active branch and unchanged source content. Abort/account epoch checks apply to compaction and chat; late writes after edit, deletion, branch/account changes are rejected. Users may inspect, edit, pin, remove or disable memory.
- Per-session Markdown/TXT exports contain the visible branch; JSON/ZIP preserve the complete tree, image originals, continuity and long memory. Structured import uses the existing validated archive and confirmation path. Full-library ZIP remains available.
- Attachment panel provides camera, gallery and file inputs, selected previews and removal. Official vision uploads accept actual JPEG/PNG/GIF/WebP only; frontend normalization is convenience, and server validates bytes before dispatch/charge. Native camera uses a narrow FileProvider output grant, without arbitrary file/content navigation.
- Native Blob transfer supports ZIP, Markdown, plain text, JSON and supported image types, with a 128 MiB limit. Document exports use the system save picker. MIME determines a safe filename extension and text must be valid UTF-8.
- Native PNG/JPEG/WebP/GIF saves go directly to `Pictures/DeepSeek/` after the trusted Blob transfer and retain original bytes. Android 10+ writes a MediaStore pending entry and publishes only after a complete copy, rolling back failed entries. Android 8/9 requests storage-write permission scoped through API 28 and waits for MediaScanner publication. A success toast follows publication.
- The per-conversation export panel offers original-file download and the existing `organize` handoff into native preparation, where users choose originals or smart organization. Organization navigation is disabled while generation is active because leaving native chat destroys its WebView.
- Image requests accept `Accept: text/event-stream`. After authenticated validation, the response starts with a comment, sends comments every five seconds, and finishes with `result` containing `{images,model}` or `error` containing `{error:{message,code?,status}}`. Streaming is one dispatch and never reconnects automatically. JSON callers still receive ordinary JSON/HTTP status. Refresh quota after the result or end of stream because response headers can precede the ledger write.
- Ordinary image generation uses durable background jobs. `POST /chat/api/image-jobs` accepts `{client_request_id,prompt}` and returns metadata (202 new, 200 existing, 409 same ID with a different prompt). `GET /chat/api/image-jobs/{client_request_id}` returns owner-scoped queued/running/completed/failed/cancelled/unknown/expired metadata, `/result` returns the completed `{images,model}`, and `POST .../cancel` explicitly cancels. Creation identity and billing are idempotent. Screen changes and disconnected callers do not cancel an accepted job.
- Image-job metadata is durable; prompt plaintext stays in process memory and only a hash is stored. Private generated results expire after 24 hours, including after service restarts. Pending work interrupted by a server restart becomes unknown and is never automatically replayed. Client-side recovery markers belong to the account's local IndexedDB and are omitted from portable archives. Startup resumes indexed pending sessions using GET requests; persisted explicit cancellation can reissue the same idempotent cancel, never a new generation. Completed images are saved atomically with the reply and its pending index is cleared.
- Ordinary chat describes a nonce-bound terminal application image action when image generation is available, with a bounded text prompt. Existing search, URL reading, safety, title and reminder extensions remain in the API request. A complete valid single action hands off to the existing durable image-job flow after the chat controller releases ownership. The actual prompt and stable request ID are persisted before creation. Raw action metadata is inert local archival evidence. API history includes a successful generation statement and actual prompt only when an image exists. Partial, malformed, refused or interrupted actions never dispatch images. A normal successful chat-to-image turn makes one chat and one image call.
- Focus, visibility and BFCache session checks keep an existing account page mounted and interactive. Confirmed expiry or changed owner/role ends that session. Portal modals use the shared positive viewport measurements independently of the chat root, so their height remains usable during temporary zero viewport readings.
- Android API 31+ registers a WebView ScrollCaptureCallback for the mounted DOM message scroll node. Trusted-page geometry drives scrollBounds and tile capture, excluding fixed title/composer. Screenshot operations temporarily suspend follow and restore the original position on end/cancel. DOM/content/session changes invalidate capture. Only loaded messages are captured. This uses public platform APIs without expanding the message bridge or altering normal scrolling.
- User-created conversation shares follow [conversation-sharing.md](conversation-sharing.md). Explicitly selected body text, images and attachment metadata become a public server copy until owner revocation. Exclude reasoning, actions, memory and unselected branches. Create/list/revoke require the current account. Public HTML/snapshot/images require the random share token. Import previews are read-only, and confirmation atomically appends verified images and original messages with source evidence. Sharing operations use no model quota.
- Private account conversation sync follows [conversation-sync.md](conversation-sync.md). Managed eligibility is required for enabling sync and accessing cloud content. The account-wide switch defaults off. Users choose whether to sync conversations and attachments, chat preferences, or both. Each scope is checked by the server. Scope changes advance the consent generation. Versioned CAS and persistent local dirty/deletion metadata protect concurrent and offline edits and preserve conflict copies. Pausing or revoking eligibility retains cloud data. Signed-in users can explicitly clear their own cloud copies and keep local data regardless of eligibility. Sync operations use zero model quota.
- Personal chat API follows [personal-deepseek.md](personal-deepseek.md). New accounts default to personal service. A user may back up the personal chat key in a separate passphrase-encrypted sync document and explicitly restore it on another device. Personal credentials use a separate encrypted browser vault and direct HTTPS transport with browser credentials omitted. Chat and compaction use the selected provider. DeepSeek-specific file and voice operations use the official service. Image generation uses an independent encrypted personal configuration or an available managed allowance. Provider changes suspend model/voice activity without ending account sync, and invalidate upload caches. Upstream file IDs require the matching provider scope. Portable and synchronized conversations exclude credential and dispatch state.
- Reply preferences apply to ordinary replies across chat providers. Persona text joins the reply system prompt. Reasoning effort applies in thinking mode and temperature applies with thinking disabled. Empty fields use the provider's defaults. Reply preferences are independent from memory prompts and follow the account when cloud sync is enabled.
- Share continuation uses authenticated `GET /chat/api/shared-conversation?share_id=...`. The service reads only the fixed DeepSeek public share endpoint, disallows redirects, applies 30-second/8-MiB bounds, forwards no account/model credentials and consumes no model quota. Preview is read-only. Confirmation atomically appends a local session, preserving original message roles, branch/source IDs, share URL, scope and raw snapshot. Only the selected branch contributes to model context. Raw snapshots remain local and portable archives retain provenance. Missing attachment originals are represented by metadata for user reupload.
- Voice input captures at the device's actual AudioContext rate and locally resamples to 16-kHz mono PCM16 WAV, with 120-second/8-MiB limits and explicit permission/startup/empty-audio errors. The ASR gateway validates WAV or Ogg Opus before counting an actual upstream dispatch and returns bounded safe errors. Recording resources are released on stop or cancellation.
- Android declares `RECORD_AUDIO` and `MODIFY_AUDIO_SETTINGS`. Web microphone requests grant only audio capture from the trusted current chat origin after runtime permission. Cancelling a WebView request clears only that request, and a pending system permission prompt can fulfill its current valid replacement without a duplicate launch.
