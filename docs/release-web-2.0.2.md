# 网页 2.0.2 高度修复

2026-11-17，用户提供 APK 中的真实错位截图：欢迎文字被顶部裁切、顶栏与底部声明挤在上方、输入框消失。此前现代浏览器正常尺寸检查未覆盖该状态，不能用旧版截图检查结论代替此故障的验证。

## 改动

- 访客与已登录聊天页面、输入区和相关弹窗使用兼容的 `vh` 默认高度，去掉对 `dvh` 的依赖。APK 最低 WebView 为 105，而该单位从 Chrome 108 起支持，参考 [Chrome 官方说明](https://developer.chrome.com/blog/new-in-chrome-108/)。
- 共享视口 hook 在未聚焦时也测量窗口高度；输入聚焦时优先使用 visualViewport，忽略零、负数和非有限值，全部不可用时保留上次正高度。不在失焦时清除有效高度回落到 CSS。
- 仅在线更新网页，APK 保持 2.0.1 / code 29，更新清单与签名安装包不变。用户完整退出并重开应用即可加载，无需卸载、清数据或重新安装。

## 证据与边界

在真实 Edge 与生产 DOM/CSS 上，以明确替换的零高度默认值复现了与用户截图一致的裁切、挤压和输入框塌缩。单纯模拟不支持单位时，访客页高度异常但输入仍可见；因此没有把 WebView 105-107 的兼容缺陷直接当作用户手机唯一根因。未读取用户手机的 WebView 版本。

网页 type、lint、build 已通过。最终构建在真实 Edge 144 的生产 DOM 上检查了访客与登录后两种布局：首次加载为 844px；模拟缩小至 500px 后输入仍在可见区域；注入 visualViewport 的 0 读数后回到有效窗口高度；全部高度来源为 0 时，聚焦、resize、失焦均保留上次有效高度。输入框高度分别恢复为 142px 和 106px。故障注入不代表已直接测得用户手机的触发来源。

旧 WebView 的隔离 CSS 诊断 fixture 通过 Android 测试 APK 编译，但模拟器 ADB 始终 offline，未执行；已停止本任务进程。该合成 fixture 不绑定生产 CSS，保留为私有诊断证据，没有加入正式回归测试套件。没有将其编译或模拟器启动日志计为设备验证通过。

私有证据为 `build/qa/viewport-hotfix/diagnosis.md`、`hook-guard-metrics.json` 和截图；所有测试均使用合成数据，无模型调用。用户手机内的完整原生桥和实际软键盘仍未直接实测。
